# Threat model

Scope: the trilium-mcp server as deployed in two shapes: a local stdio child
process, and an internet-reachable Streamable HTTP service behind a reverse
proxy. Trilium itself stays on a private network; only this facade is exposed.

## Assets

1. The Trilium ETAPI token. It grants full read/write on the whole knowledge base.
2. Note content and metadata (personal, sometimes sensitive).
3. Integrity of notes (no silent overwrites, no lost edits).
4. Availability of Trilium (the MCP server must not become an amplifier).
5. Audit trail integrity.

## Trust boundaries

```
cloud agent ──HTTPS──▶ reverse proxy ──▶ trilium-mcp (HTTP) ──private──▶ Trilium ETAPI
local agent ──stdio──▶ trilium-mcp (stdio) ────────────────────private──▶ Trilium ETAPI
```

- Everything arriving over HTTP is untrusted until the bearer token verifies.
- Everything inside notes and search results is _data_. It is never interpreted
  as instructions by the server, and the server instructions tell the model the
  same. The server has no code paths that evaluate note content.
- The stdio process trusts its parent (the agent host) and gets scopes from its
  environment; there is no network authentication because the process boundary
  is the boundary.

## Threats and mitigations

| #   | Threat                                       | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Residual risk                                                                                                                                                                                            |
| --- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | Token leakage to clients                     | The ETAPI token is read from the environment, sent only to `TRILIUM_API_URL`, never included in tool output, and redacted from logs by key-name matching (`token`, `secret`, `password`, `authorization`).                                                                                                                                                                                                                                                                                                                                                                                                                                           | Misconfigured `TRILIUM_API_URL` pointing at an attacker host would leak it; validated as http(s) URL only. Keep it in the deployment secret store.                                                       |
| T2  | Unauthenticated remote access                | `MCP_AUTH_MODE=none` is refused on non-loopback binds unless `MCP_DANGEROUSLY_ALLOW_UNAUTHENTICATED=true`. OIDC mode verifies signature (JWKS), issuer, audience, expiry; static mode uses constant-time comparison and ≥16-char tokens. Missing/invalid tokens get RFC 6750 challenges pointing at RFC 9728 metadata.                                                                                                                                                                                                                                                                                                                               | Token theft from a client. Short-lived access tokens (Auth0 default 24h; set lower) and refresh at the IdP.                                                                                              |
| T3  | Scope escalation                             | Tools are registered per request from the verified scopes, so an unauthorised tool is not even listed; the handler re-checks scope before running. Scopes come from the first present delegated-scope claim (`scope`, then `scp`); a token with neither gets no scopes, and Auth0's user-wide `permissions` claim is never read unless configured explicitly. `trilium.admin` unlocks only the destructive tools (`delete_note`, `undelete_note`, `delete_attachment`).                                                                                                                                                                              | Scope claims are trusted from the IdP; configure the IdP so only intended clients can request `trilium.write`.                                                                                           |
| T4  | Prompt injection via note content            | Content is returned as data in `structuredContent`; server never acts on it. Instructions to the model say so. Tool descriptions never reference dynamic data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | The _model_ may still follow injected text. Out of scope for the server; mitigated by read-only scopes for exploratory agents.                                                                           |
| T5  | Lost updates / concurrent overwrite          | `patch_note` requires `expectedHash` (Trilium blobId); the read, re-check, revision and write run under a per-note lock, so two same-hash writes in one process yield one success and one `CONFLICT`. A failed revision aborts the write.                                                                                                                                                                                                                                                                                                                                                                                                            | ETAPI has no conditional PUT: writers in other processes (Trilium UI, a second replica) are only caught by the re-check before the write. Run one replica; revisions make the residual race recoverable. |
| T6  | Duplicate creation on retries                | `idempotencyKey` (per principal, 24h, in-memory): concurrent identical requests wait for the first to finish and receive its outcome, a key reused with a different payload is rejected, and the note is checkpointed as soon as it exists so a failure later in the call yields an honest `INCOMPLETE` replay instead of a second note. Duplicate-title checks are serialized per (parent, title).                                                                                                                                                                                                                                                  | In-memory store: a restart or a second replica forgets keys and locks. Run one instance; `DUPLICATE` errors are the backstop.                                                                            |
| T7  | Oversized requests / memory exhaustion / CPU | Body cap (413), content write cap, streamed reads that stop at `maxContentBytes` (the rest of the body is discarded, not buffered), match/context caps, cursor offset cap, fixed ascending window, children and page-size caps. Edit output is assembled under the write byte budget and rejected as `TOO_LARGE` before it is built or scanned; replacement templates are parsed once and charged (tokens × matches, across all edits of a call) against a fixed work budget before expansion, so zero-byte substitutions cannot stall the event loop. Caller regexes run in a worker thread with a wall-clock budget and are terminated on overrun. | Trilium search itself can be expensive; the rate limiter bounds call volume. Worker start costs a few ms per regex call.                                                                                 |
| T8  | Request flooding (DoS on Trilium)            | Per-principal token bucket (`MCP_RATE_LIMIT_*`); anonymous callers keyed by the socket peer (forwarding headers only with `MCP_TRUST_PROXY`); `/healthz` is rate limited and reuses one upstream probe per 15 s. ETAPI timeouts and bounded retries (GET only).                                                                                                                                                                                                                                                                                                                                                                                      | Token verification itself costs CPU before the limiter; distributed flooding needs proxy-level limits.                                                                                                   |
| T9  | DNS rebinding / browser-originated abuse     | Host and Origin validation (SDK middleware): automatic on loopback binds; off loopback the Host allow-list is required and Origin defaults to the same hostnames.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Requires the proxy to pass the public `Host` through.                                                                                                                                                    |
| T10 | Injection into Trilium search DSL            | Values are quoted with the rule verified live (single quotes, double quotes when the value contains `'`, backslash-escaped otherwise); attribute names are validated; note ids match `[A-Za-z0-9_]{1,64}`; the raw `query` escape hatch is limited to callers who already have read scope and can only run searches.                                                                                                                                                                                                                                                                                                                                 | A read-scoped caller can craft arbitrary _searches_ via `query`. That is the intended capability; there is no write path through search.                                                                 |
| T11 | Path traversal in ETAPI paths                | Every entity id is validated before URL construction.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | —                                                                                                                                                                                                        |
| T12 | Log-based leakage                            | Audit records carry principal/client/subject, tool, note ids, outcome, latency, and for rejected calls only the offending argument names; never titles, bodies, search terms, argument values or tokens. Tool failures are logged as facts (codes, upstream status/path) rather than messages, because upstream messages can echo search text; a canary test guards this.                                                                                                                                                                                                                                                                            | Note ids are quasi-identifiers; protect log storage accordingly.                                                                                                                                         |
| T13 | Replay of captured bearer tokens             | Expiry enforced; audience bound to `MCP_PUBLIC_URL` so a token for another API is rejected.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Tokens are bearer tokens; TLS at the proxy is mandatory. DPoP not implemented.                                                                                                                           |
| T14 | Cross-user data access                       | Single-tenant by design: every principal reaches the same Trilium. Authorization is "may this client call this tool", not per-note ACLs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Do not grant `trilium.write` to automations you would not trust with the whole knowledge base.                                                                                                           |
| T15 | Supply chain                                 | Small dependency set (SDK packages, hono, jose, marked, zod); lockfile committed; container built from `node:24-alpine`, runs as non-root, production deps only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Keep `npm audit` in CI.                                                                                                                                                                                  |
| T16 | Health endpoint leakage                      | `/healthz` returns only status, reachability, and server version.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | —                                                                                                                                                                                                        |
| T17 | Destructive tools misused by a model         | Deletion lives behind `trilium.admin`, which write-only principals never see. `delete_note` needs `confirm=true` and `expectedTitle` equal to the current title (a read is forced), refuses subtrees without `deleteDescendants`, offers `dryRun`, never touches root or `_`-prefixed system notes, and verifies the note is gone. Trilium soft-deletes, so `undelete_note` reverses it inside the retention window. `move_note` creates the new branch before deleting the old one, so a failure leaves the note in two places rather than none. Attachment deletion needs `confirm`.                                                               | Attachment deletion and erased notes are not reversible; the retention window (7 days by default) is Trilium's. Grant `trilium.admin` to a human-driven client only.                                     |
| T18 | Binary payloads (memory, SSRF)               | Binary bodies arrive only inline as base64 / data: URIs; the decoded size is computed from the encoded length and rejected against `MCP_MAX_WRITE_CONTENT_BYTES` before decoding. Reads are streamed and stop at `maxContentBytes`; a cut binary body is omitted with its size rather than returned partially. No URL fetching and no server file paths, so the server cannot be used to reach other hosts or read its own filesystem.                                                                                                                                                                                                               | Base64 inflates transport size by a third; the HTTP body cap still applies. Trilium's own attachment size limits apply upstream.                                                                         |

## Non-goals

- Per-note authorization or multi-user isolation.
- Protecting against a compromised agent host running the stdio process.
- Hiding the existence of the endpoint (it is authenticated, not secret).
